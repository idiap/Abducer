How work moves through the workflow system

The declared architecture groups 4 workflows into 1 families. Forward edges carry typed handoffs through each ordered stack, while shared hooks couple workflows and dashed returns preserve review or refinement loops.

Start with one family and follow its ordered handoffs. Then inspect shared hooks for cross-stack coupling and feedback returns for iteration or closure behavior.

  • Forward handoff One hook materializes the typed input consumed by the next hook.
  • Shared hook The same skill participates in more than one workflow stack.
  • Guarded return A critic, refiner, or guard can return findings to an earlier decision surface.

Representation Choice

  • Use small multiples: workflow hierarchy, ordered hook sequence, shared-skill reuse, reflective loop, and detailed stack lanes.
  • Keep workflow sequence explicit with family -> workflow -> ordered step hierarchy and next-step edges.
  • Keep loops separate from linear stack order so critic/refiner/guard behavior is visible without tangling every edge.
  • Show hooks as ordered chips inside collapsible lanes; this preserves hierarchy while keeping the first screen readable.
  • Use an interactive Cytoscape.js layer for granular skill-to-skill edge inspection, with static SVG views as the durable fallback.
