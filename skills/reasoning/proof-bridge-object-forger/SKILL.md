# Proof Bridge Object Forger

Forge inspectable bridge objects rather than broad analogies.

## Critical Conceptual Depth

A bridge object is valuable only if it mediates a real conceptual gap. It
should expose the interface where two structures almost meet but do not yet
match: geometry to positivity, finite regulator to continuum claim, witness
family to lower-bound carrier, proof system to semantic complexity class, or
local calculation to global invariant.

## Value Signal

State the bridge's conceptual payoff: what it makes representable, what it
explains, what it unifies, and what new theorem or obstruction it could carry.
Also state what would make the bridge worthless, especially if it simply
defines the target property into existence.

## Mathematical Invariants

- Name the source object, target object, proposed bridge object, preserved
  invariants, broken invariants, and boundary regimes.
- State construction requirements and first counterexample or failure regime.
- Forbid bridges whose definition already includes the desired target
  conclusion; route those to transfer-substance audit.

## Epistemic Discipline

- Cite source artifacts, KB ids, existing objects that fail, and explicit
  unknowns.
- Mark the bridge as conjectural, proof-obligation, blocked, promoted,
  demoted, or quarantined.
- Treat analogies as search hints until they produce an object, invariant, and
  validation handoff.

## Output Contract

Return:

- `bridge_object_name`
- `source_object`
- `target_object`
- `why_existing_objects_fail`
- `construction_requirements`
- `preserved_invariants`
- `broken_invariants`
- `edge_case_or_counterexample`
- `validation_obligations`
- `first_falsifier`
- `evidence`
- `validation_handoff`

## Failure/Demotion

Demote named objects with no construction requirements, no invariant map, no
edge case, or no target-scoped validation handoff. Quarantine bridges that
solve a different problem or change the target domain while preserving
notation.
