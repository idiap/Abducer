# Framework Paper Validator

For conceptual-organization requests, follow [the shared conceptual inquiry contract](../framework-core-mechanism-curator/references/conceptual-inquiry-contract.md). Manually verify the argument's situation/tension, grounded diagnosis and exit, substantive alternatives, six source-profile lens dispositions with real changes, preserved successes/differences, plural trade-offs, understanding delta, and correction conditions. Reject an operator-first taxonomy disguised by headings or a speculative preference promoted to truth. Check that formal/operator annotations support rather than organize the main explanation. Keep this manual semantic review distinct from script results and preserve the full prior step explanation gate.

Validate structure and scientific claim discipline separately.

1. Confirm all manifests and section sidecars share the frozen input digest.
2. Resolve every claim, evidence locator, section, figure, label, reference, and citation.
3. Reject unlicensed strong verbs, absolute user paths, secret-like text, private traces, shell escape, raw HTML, and unresolved placeholders.
4. Require an evidence-status evaluation section and a limitations section even when results are unavailable.
5. Verify the build-manifest digest. When `latexmk` is available, require a successful local compile and emit `main.pdf`; otherwise report compilation as unavailable.

Run `scripts/validate_paper.py`. A failing report blocks assembly promotion but does not erase partial-stage receipts.

For a skill-authored Prism workflow appendix, independently check extraction/model/fragment
digest links, selected and omitted workflow coverage, typed arrow endpoints, explicit
adapters and assumptions, branch/guard/loop preservation, and every equality claimed by
a diagram. Free-path identity and associativity do not establish semantic equivalence,
termination or execution success. Report this manual appendix review separately from
the fixed-section script's verdict; it does not validate the new packet contracts.

For dependent-type prose, additionally check context formation, binder scope,
value-index dependence, capture-avoiding substitution and the premises of each
displayed judgment. Distinguish definitional conversion from identity witnesses
and explicit transport. Preserve wrapper projections and branch-local assumptions;
reject changing an assessment's claim index without justification. Label proposed
refinements and declared postulates, and keep generated data, certificates and
scientific proof separate. Report manual derivation review as manual; neither
LaTeX compilation nor this script is a dependent type checker.

For workflow examples, compare original source/blueprint scope with accepted example
workflow IDs: reject missing coverage, duplicate generic cases and silent scope reduction.
Inspect actual input, intermediate reasoning, distinctive mechanism, useful outcome and
formal value bindings; a workflow name, status change or source pointer is not an example.
Check illustrative/observed status and independently justified mathematical calculations.
Verify one final section owner, parent merge and child/parent byte hashes. Record these
manual content checks separately from the fixed-section validator script.

For taxonomy/type figures check model-to-rendered node, membership and named-port
coverage; input direction is type-to-operation and output direction operation-to-type.
Confirm wrappers, multi-input bundles and unknown classification remain visible.
Distinguish group membership, subtype and proposed refinement in both edge style and
legend. Inspect real rendered output for clipping, collisions, overly small text and
long labels at final page size; a parseable SVG is not a visual-quality verdict.
Resolve figure claims, vector file hashes, captions and sole parent-section ownership.

## Mandatory step explanation gate

Read [the shared step explanation contract](../framework-paper-workflow-appendix-writer/references/step-explanation-contract.md) for occurrence-level paper revisions.

Run scripts/step_explanations.py in the manual appendix lane. Require exact binding coverage and current source hashes, seven fields, continuous case review and content-bound per-workflow verdicts. Report deterministic coverage separately from manual semantic review. Missing review blocks completion even if LaTeX builds. For structured-description requests, check that all seven display fields remain separately readable, Input/Output name actual scientific content, and Output does not absorb continuation. Manually check that shorter wording preserves premises, quantifiers, joins, unresolved producers and epistemic status; label counts alone cannot establish this.

## Recursive goals and workflow relationships

When this explanation is requested, read [the shared recursive-goals contract](../framework-core-mechanism-curator/references/recursive-goals-and-workflow-relations.md). Run the contract's behavioral challenges manually and reconcile complete workflow IDs, actual inclusion and source bindings. Counts and a successful build do not verify parent closure, logical dependency sufficiency, or runtime termination. This is a manual authoring extension, not a new fixed-runner schema or stage.
