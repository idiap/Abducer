# Artifact Contracts

This document defines the interoperable artifact shapes across skills.

## 1) KB File Contract (`KB/*.kb.md`)

Front matter follows `KB/problem-template.kb.md` and statements are fenced YAML blocks.

Required statement fields used by scripts:

- `id` (string, e.g. `st.thm.example`)
- `kind` (`definition|axiom|theorem|lemma|corollary|conjecture|observation`)
- `status` (`accepted|tentative|rejected`)
- `latex` (string)
- `informal` (string)
- `depends_on` (list of statement IDs)
- `source_ids` (list of source IDs)

Optional but consumed in scoring/explanations:

- `used_symbols`
- `concept_roles`
- `method_tags`
- `barrier_family`
- `confidence`
- `proof_sketch`
- `notes`

## Looper Control-Plane Contracts

The Looper integration adds a target-oriented control plane around the existing
KB artifact chain.

### Target Packet

Validated by:

- `agentic/scripts/validate_target_packets.py`

Canonical example:

- `agentic/examples/targets/p-vs-np-target.json`

Required fields include:

- `target_id`
- `raw_goal`
- `kb_path`
- `main_claim_ids`
- `desired_output_type`
- `quality_criteria`
- `acceptance_gates`
- `known_constraints`
- `unknowns`
- `validation_targets`
- `evidence_paths`

### Dependency Graph

Generated by:

- `agentic/scripts/build_target_dependency_graph.py`
- `agentic/scripts/run_target_navigation.py`

Validated by:

- `agentic/scripts/validate_dependency_graph.py`

Canonical P vs NP output:

- `agentic/state/dependency_graphs/p-vs-np.json`

Graph nodes carry:

- `id`
- `kind`
- `status`
- `label`
- `source_artifact`
- `evidence_paths`
- `parents`
- `next_action`
- `blocker`

Open nodes must have a `next_action` or `blocker`.

### Workflow Registry

Validated by:

- `agentic/scripts/validate_task_skill_registry.py`

Canonical P vs NP workflow:

- `registry/tasks/p-vs-np-target-navigation/task_registry.json`

The visible unit is `visible_workflows`; skills and hooks are supporting
composition elements.
