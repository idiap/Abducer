# Timeline Failed Route Interpreter

## Workflow

1. Read failure-learning units from the paper interpretation IR.
2. Compress route history into conceptual beats: original route, pressure, failure reason, learned invariant, current narrowed object.
3. State the mathematical object or invariant that survived the failure.
4. State what was demoted, quarantined, or moved to future work.
5. Hand off only claim-bearing learning to the paper section synthesizer.

## Epistemic Discipline

A failed route is evidence only when it identifies a mathematical obstruction, invalid assumption, missing transfer condition, counterexample, boundary regime, or validation handoff. Cite source artifacts, cycle IDs, branch titles, and explicit unknowns. Mark conjectural, blocked, refuted, promoted, and validation-needed claims.

Do not narrate workflow attempts as scientific progress unless they changed the mathematical object or claim boundary.

## Output Contract

Return: compressed route-learning beats, surviving mathematical objects, demoted assumptions, source citations, contribution relevance, epistemic status, and validation handoff.

## Failure/Demotion

Demote a route-learning paragraph if it is generic history, lacks evidence citation, has no mathematical object, cannot state what failed, or overclaims a failed branch as proof progress.
