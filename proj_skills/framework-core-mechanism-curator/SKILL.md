# Framework Core Mechanism Curator

Produce `CoreReasoningMechanismModel` version `2.0.0` using [the model contract](references/core-mechanism-model-contract.md) and [the shared conceptual inquiry contract](references/conceptual-inquiry-contract.md). This manual authoring lane organizes a conceptual argument from frozen evidence. It does not execute workflows, add a runner stage, or edit the manuscript.

Require the frozen `RepositoryEvidenceIndex`, compatible `FrameworkAbstractionModel`, paper audience and question, and source packets for relevant conceptual prescriptions and native workflow facts. The manuscript records its presentation, not independent implementation evidence. Missing conceptual evidence returns to extraction; native declarations alone cannot supply invented procedures.

For an authorized revision of an existing manuscript in the manual lane, a frozen
local source selection with exact paths, spans and hashes may supply the evidence
basis alongside the already reviewed native packet. Record this as a
`manual_frozen_source_index`, with a separate descriptive claim ledger and source
review; do not call it a schema-validated `RepositoryEvidenceIndex` or fixed-runner
acceptance. New claims still require source support or explicit illustrative status.

1. Reconstruct the conceptual situation, incumbent primitives/relations/representations, explanatory ideal, protected successes, opacity, and genealogy. Locate the strongest opposing commitments and exact tension before inventorying implementation operators.
2. Diagnose whether the bottleneck calls for conceptual, representational, or explanatory revision. Preserve a grounded `not_conceptual` exit to ordinary calculation, reading, formalization, proof, or measurement. An unresolved diagnosis is not permission to invent a crisis.
3. Articulate materially different alternatives while retaining the incumbent. Explain changes to primitives, identities, relations, mechanisms, representations, or equivalence policies; preserve successful regimes and decisive differences. Select explanatory anchors by their role in this inquiry, not by an eight-primitive inventory or a closed primitive/composition/motif taxonomy.
4. Apply the shared contract's six focus lenses where warranted. For each record assumption exposed, protected content, mutation or justified `no_change`, and new risk; retain reasoned `not_applicable` and `blocked` dispositions. Supporting source lenses remain available. Explain actual conceptual change rather than philosophical labels.
5. Compare rivals plurally with explicit trade-offs and support boundaries. Record before/after understanding, remaining opposition, new consequences and questions, correction conditions, and the next reflective or formal/evidential obligation. Never turn theoretical preference into truth or force a scalar winner.
6. Give each selected explanatory anchor a concrete case, visible intermediate change, useful consequence, and discriminating contrast. A connected running case should carry the conceptual problem through revision; not every explanation needs a different example. Native operator families are optional many-to-many source annotations, never stages or universal exhaustive cognition.
7. Plan the main argument around these questions before formal support. Preserve unknown execution order, unresolved native producers, exact claim/target identity, and distinctions between declaration, prescription, illustration, and observed results. Keep all 19 workflows and 65 currently frozen occurrence explanations under the independent step contract; reopen manifest scope on regeneration.

Write `core-reasoning-mechanism-model.json` and a curation report under the isolated paper run root. Manually review source bindings, diagnostic honesty, actual conceptual change, lens dispositions, preserved differences, plural comparison, and correction conditions. Route candidate claims through `$framework-paper-claim-curator`, then send the argument to `$framework-paper-blueprint-author` and reviewed model to `$framework-paper-core-mechanism-writer`. Report unresolved rows and checks performed. Legacy `1.0.0` packets require explicit re-curation for this lane; changing their version field alone is not migration.
