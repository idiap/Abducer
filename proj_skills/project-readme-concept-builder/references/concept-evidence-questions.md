# Concept Evidence Questions

Use only when the project's public identity or claim boundary is unclear.

## Promise

- Who supplies the input?
- What input is accepted today?
- What transformation does the executable system perform?
- Which output changes the user's next decision?

## Reasoning Model

- What does the system first observe or extract?
- What internal model does it construct?
- Which risks, contradictions, or alternatives does it test?
- What does it generate?
- How does it calibrate what the result proves?

## Differentiator

- Which difficult decision does the system make beyond producing plausible text or code?
- Which evidence remains traceable in the output?
- Which uncertainty is kept visible?

## Boundaries

- Is execution local, provider-backed, simulated, formal, or report-only?
- Are reference solutions hidden from the reasoning path?
- Does a passing syntax or unit check establish behavioral correctness?
- Which statement would a skeptical domain expert reject as overclaiming?

## Compression

Keep a detail in the root README only when it answers one of these questions:

1. What is this?
2. Why should I care?
3. Can I run it now?
4. What will I get?
5. Where do I go next?

Move everything else to the owning guide, concept document, integration page, or reference.
